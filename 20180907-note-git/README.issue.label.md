在 GitHub 项目中，关于**需求（issue）**，通常会用以下几种常见的标签（label）来标记，以便清晰分类和管理：

1. **enhancement**：
   - 用于表示功能增强或新需求。通常适用于用户或开发者提出的改进请求。
   
2. **feature** 或 **feature request**：
   - 用于标记新功能需求，适合那些与新特性开发相关的 issue。
   
3. **bug**：
   - 如果需求 issue 是为了修复现有的功能问题，可以使用 bug 标签，但这一般是修复问题，而非需求。
   
4. **help wanted**：
   - 用于需要协助处理的需求或功能开发。通常表明这个需求 issue 需要贡献者的帮助。
   
5. **discussion**：
   - 如果需求仍然需要更多的讨论或设计考虑，可以用该标签来表示讨论阶段。

6. **priority: high/low**：
   - 对需求进行优先级的标注，帮助团队了解哪些需求应该先实现。

7. **question**：
   - 当需求还不完全明确，或者需要澄清细节时，可以标记为 question。
