要实现 Git 默认不走代理，只有在无法访问时才走代理

### 1. 配置 Git 使用代理（按需启用）

首先，可以通过 `git config` 命令设置代理：

```bash
git config --global http.proxy http://your_proxy_address:port
git config --global https.proxy https://your_proxy_address:port
```

### 2. 设置默认不使用代理

然后，通过修改 `.gitconfig` 来配置代理，只在必要时启用。在 Git 配置文件中，我们可以设置 `no_proxy` 环境变量，来告诉 Git 在访问某些地址时不使用代理。比如，你可以设置在访问某些特定的 URL 时不走代理。

```bash
git config --global http.noProxy "*.<domain>"
```

例如，如果你想在访问 `github.com` 时不使用代理：

```bash
git config --global http.noProxy "github.com"
```

### 3. 使用代理时，配置一个代理脚本（根据访问失败时切换代理）

如果想在网络不可用时自动启用代理，可以使用一个小脚本来判断网络状况，并根据条件启用或禁用代理。

你可以创建一个自定义的脚本，比如 `git-proxy.sh`，该脚本可以在 Git 访问失败时启用代理：

```bash
#!/bin/bash

# 检查是否可以访问 GitHub（例如）
if ! curl -s https://github.com > /dev/null; then
  echo "GitHub access failed, enabling proxy..."
  git config --global http.proxy http://your_proxy_address:port
else
  echo "GitHub access is working fine, disabling proxy..."
  git config --global --unset http.proxy
fi
```

你可以将此脚本与 Git 操作结合使用（比如每次使用 Git 拉取操作前运行该脚本）。脚本会先检查访问是否正常，若不能访问，则启用代理。

### 4. 配置环境变量（在需要时启用代理）

有时，你可以通过设置环境变量来实现代理的条件启用。在 Windows 或 Linux 系统中，可以通过设置 `http_proxy` 和 `https_proxy` 环境变量来控制是否启用代理：

```bash
export http_proxy="http://your_proxy_address:port"
export https_proxy="https://your_proxy_address:port"
```

如果你不希望每次都手动启用代理，可以在需要时运行一个自动检测代理的脚本，根据访问结果决定是否启用代理。

### 总结

- 默认情况下，可以通过 `git config --global` 设置代理。
- 通过 `noProxy` 配置使 Git 在访问特定站点时不使用代理。
- 如果需要根据网络情况自动切换代理，可以编写脚本或使用环境变量来实现。
